## 实证（本轮开发中真实撞到，不是假设）

同一句「你最新记忆是什么」，两条通道给出**不同答案**：

- 联想通道（`prep.py --query "最新 今天 昨天 刚刚 最近"`）→ 返回 2026-09-29 / 10-01 / 10-09 / 09-07 / 08-31，**全是旧的**。原因：它是相关性排序，`最新` 这种词在向量空间里不等于"日期最大"，反倒被长日记的语义相似度带偏。
- 确定性通道（`recall.py --timeline 5`）→ 2026-10-21 / 10-21 / 10-20 / 10-17 / 10-16，**正确**。

也就是说：在没有 `--timeline` 之前，AI 回答"你最新记忆在哪天"**只能靠猜或去翻 md**——而 2026-10-21 那轮真实体检里，我确实答错了（说停在 9/22，实际库里到 10/21）。这正是 Issue 描述的缺口，本轮补齐。

## 顺带修掉的三个静默失败

1. **日期比较漏当天**：`'2026-09-22 10:00:00' > '2026-09-22'` 为真 → `--until` 漏掉当天。已统一 `substr(...,1,10)`。
2. **非法日期静默返空**：`--since 2026-9-1`（未补零）不报错、只返回"暂无记忆"，把参数错误伪装成"我没记过"。已改为严格校验 + 退出码 2。
3. **`--literal` 吞掉下一个 flag**：PowerShell 丢空串时 `--literal "" --identity X` 变成 `--literal --identity X`，把 `--identity` 当搜索词。已改为缺值显式报错。

另修一处**骗人**的拼接：字面命中非连续块时，原来直接 `\n\n` 拼接，读者会以为两段正文相邻。现在中间插 `…`。

## 环境备注

跑全量测试期间 C 盘一度被 `tempfile` 泄漏的临时库塞满（`database or disk is full`），不是代码问题；已清理 500+ 个临时库目录。既有测试的 `TemporaryDirectory(ignore_cleanup_errors=True)` 在 Windows 上会漏掉 `recall.db`，属既有行为，本轮未改（范围外，但值得单开一票）。

## 第二条实证：库比 md 更完整

qinglan 区实测：库内 508 条 file 记录 vs 磁盘 505 个 `.md`，其中 **2 条记录的源 md 已被删除**，`--timeline` 仍能返回它们的内容。

这条比第一条更能说明问题：**md 不是可靠的真值来源**——它是"写入当时"的源，不保证长期存在。检索若依赖 md，就会随文件丢失而丢记忆；检索走库，删了 md 也照样答得出。

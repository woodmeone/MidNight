## 用户故事

作为记忆的使用者（赖老师），我想要 AI 回答「你还记得我吗 / 这事记到哪一天 / 有没有提过 X」时**只走 recall 的检索通道**，以便记忆的答案永远来自联想算法与记忆库（受身份隔离、标签网、时间加权、预算约束），而不是靠翻 `dailynote/*.md` 原文蒙对。

## 背景 / 为什么要变

真实事故（2026-10-21）：用户用一个纯检索指令考记忆（"最新的数据在哪 / 当老师相关的记忆最新在哪 / 随记记到哪天"），并明确禁止读文档。结论是合格，但过程中暴露出一个结构性漏洞：**md 源文件同时被当成"源"和"索引"**。

第一性拆解——为什么 AI 会去 grep/read dailynote：

1. **能力缺口**：有三类问题联想召回天生答不了。它是"相关性排序"，不是"聚合/精确查询"：
   - 时间轴类："最新一条是哪天"、"记到哪一天"、"9/22 之后还有没有"；
   - 精确字面类："有没有提过'中立不追究'这个词"；
   - 边界类："某天之后全部"。
   没有正解时，翻文件是唯一能答的路，于是翻文件变成理性选择。
2. **成本错觉**：读文件一次调用就确定，召回要拼 query、还要赌相似度。
3. **无痕迹**：走没走算法不可验证，所以"我走了联想"只能靠自述。

代价（不是洁癖，是真损失）：
- 绕过**身份隔离**（`dailynote/` 是明文目录，grep 一下就能跨 agent 读别人的记忆）；
- 绕过**标签共现网与时间加权**——回到关键词命中的旧世界，联想能力形同废置；
- 绕过**去重/预算**，长日记整篇灌进上下文；
- 依赖**文件系统可读**：迁到 hook 运行时 / 远端 / 容器时 dailynote 不一定在，算法才是可移植的那条路；
- 让"记忆"降级成"文本搜索"，和 SKILL.md 宣称的能力不一致。

追溯链（不变量 5）：检索侧既有设计意图写在 `docs/associative-optimization-spec.md`（票 T1–T4：tag-first 门控、深联想阈值、衰减保序、倒排+缓存）——一切优化都在"库内联想"这条线上，**没有任何一票把 md 当检索索引**。本次不推翻它们，只补齐它们的盲区。

## 验收标准

- [ ] `SKILL.md` 有「检索通道铁律」：默认=联想通道；md 源文件**永不作为检索目标**；只有用户显式说"读原文/看文件"才允许，且回复里必须声明是授权通道。
- [ ] `SKILL.md` 有「查询派生协议」：回复前 AI 从上下文抽 2–5 个名词性线索 + 对象 anchor 拼 `--query`（不是把寒暄原话丢进去），默认 `--multi-scale`。
- [ ] `recall.py` 新增确定性通道（同库、同身份、同输出格式、不读 md）：`--timeline N`、`--since`、`--until`、`--literal "词语"`。
- [ ] `--timeline/--literal` 必须显式带 `--identity/--agent`；缺身份直接报错退出（2），不得静默落到 env/default 库。
- [ ] 同一条日记被切成多块时，时间轴/字面结果按 **file 级去重**，块按 `chunk_index` 顺序拼接。
- [ ] 每次 CLI 检索追加一行留痕到 `<agent>/retrieval_ledger.jsonl`；`--audit [N]` 能打印；留痕失败**不得**影响检索结果。
- [ ] 留痕按 agent 物理隔离（不同 agent 的 ledger 互不可见）。
- [ ] 默认行为逐位不变：不给新 flag 时，`recall.py` / `prep.py` 的输出与改动前完全一致（既有 265 passed 不回归）。
- [ ] 对抗测试：把 `dailynote/` 目录整体移走后，`--timeline` 与 `--literal` 仍能答（证明检索不依赖 md）。
- [ ] `PROJECT.md` / `CONTEXT.md` 回写：新增术语"联想通道 / 确定性通道 / 检索留痕"，模块地图补 `ledger.py`。

## 范围外（本轮不做）

- 不做"物理隔离 md"（加密/移出可读区）——会破坏"md 是真相源、永不删"的既有约束，且要重写 ingest/备份链路。
- 不改 `prep.py` 的默认输出（不自动追加时间轴），避免隐藏行为变更、破坏"关闭时逐位等于旧行为"约束。
- 不做远程/服务端检索通道（`docs/server-side-plan.md` 另议）。
- 不做关键词抽取的模型化（抽词是上层 AI 的职责，脚本只提供注入点 `--query`）。

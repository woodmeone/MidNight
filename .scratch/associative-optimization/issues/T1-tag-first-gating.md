# T1 · tag-first 前置门控（核心，最痛，最先）

**Status**: ✅ DONE 2026-09-08（与 T2 一并实现）
**实现**: `expand_tag_candidates()` + `TAG_CANDIDATE_CAP`，`recall_associative` 改用它

**Blocked by**: 无
**Spec**: P0 / §4.1 铁律2
**目标接口**: `recall_associative` 签名不变。

## 做什么
把 `recall_associative` 的链路从 **KNN 先行、tag 事后抬分** 改为 **tag 事前进候选筛选**：
1. embedding 查询 → 预感应 Core/Ghost 标签（`activate_tags`，已实现）。
2. **候选筛选不再只看向量**：保证 `top-N` 中必须有"命中核心标签"的 chunk。
3. tag 从"事后投票改排序"升级为"事前框定检索方向"。

## 为什么（应用例子）
- **例（真实翻车）**：赖老师问"张娜啥时候问我问题"，我拿"张娜+英语"召回，结果全是 9/3 的"英语阅读策略"，漏了 9/7 的"番职大金融科技"。
  - **现状**：KNN 先按"英语"similarity 框住了候选 → tag 只能在框内抬分 → 金融科技那条进不来。
  - **改后**：查询先感应到"张娜/升学/问"为核心标签 → 候选节点=带这些 tag 的 chunk → 金融科技那条**本来就在框内**，直接命中。
- **验收对齐**：以"张娜 升学"为 query，联想召回必须命中 9/7 金融科技条目，而非被"英语"吞掉。

## 关键设计
- Core tag 的界定沿用 `CORE_RATIO`（相对最优相似度比例），确保弱哈希噪声不成为硬约束。
- tag 门控与向量分数**加权重叠**：既保证"必含核心标签项"，又保留向量相关性排序。
- 参数（k/budget/threshold）**锁死为安全默认**，AI 不可逐次乱调（§4.1 铁律2）。

## 验收
- 已有 157 测试全绿；`recall_associative` 签名不变。
- 新增红→绿用例：`test_tag_first_gating.py`——"张娜 升学"命中金融科技，"张娜 英语"仍命中英语策略（两不串）。

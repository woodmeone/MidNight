## 用户故事

作为记忆的使用者（赖老师），我想要「**十月以后关于备课的进展**」这种**时间 × 语义**的混合问题一次问出口，以便不用先查时间轴、再查联想、再自己对齐两个结果。

## 背景 / 为什么要变

上一轮（#5）把检索拆成三条通道：联想（默认）、确定性（时间轴/字面）、md 原文（例外）。这个拆法解决"答不了日期问题"的问题，但**拆过头了**：

```bash
recall.py --query "备课 教案" --since 2026-10-01 --identity qinglan
→ Usage: --since/--until 只能与 --timeline 或 --literal 一起用
```

于是"十月以后跟备课有关的"只能两次调用：

```bash
recall.py --timeline 10 --since 2026-10-01   # 拿时间线（按日期，不带语义）
prep.py --query "备课 教案"                   # 拿语义（**不受时间窗约束**，可能捞回八月的备课）
```

用户得自己把两个结果在脑子里对齐，而且第二次召回的候选池根本没被时间窗约束——语义那条腿是"越界"的。

这暴露了 #5 的概念错误：把**同一件事的两个维度**（相关性 vs 时间范围）误当成**两种不同的东西**（两条通道）。

## 要做成什么样（第一性）

正确的形态不是"三条通道"，而是**一条联想主干 + 两个可选约束**：

```
候选池（全库 / 倒排预筛）
  → 【约束A】时间窗：substr(COALESCE(diary_date, created_at),1,10) BETWEEN since AND until
  → 【约束B】字面谓词：content LIKE %字面%   （等价于把约束直接压进候选池）
  → 向量 KNN + 标签脉冲 + 时间加权 + tag-first 扩增 + MMR   ← 联想算法**原封不动**
  → 去重 → 预算 → 注入
```

差别是本质的：约束是**过滤候选池**（决定"在哪些记忆里找"），联想是**排序**（决定"哪条最像"）。取交集比串行两次调用更准，也少一次调用。

`--timeline` / `--literal` 不废掉——它们是"约束的退化形态"（只有约束、不做语义排序），回答"最新一条是哪天 / 有没有提过某词"这类不需要排序的问题，仍然有用。

## 验收标准

- [ ] `recall.py --query "..." --since A --until B` 可用：时间窗在**候选池阶段**过滤，而不是取完 top-k 再筛（否则会少返回、甚至空）
- [ ] 时间窗同样约束 **tag-first 扩增**（`expand_tag_candidates`）——否则标签把窗口外的记忆捞回来，窗口就是漏的
- [ ] 时间窗参与**缓存键**：同一 query 带窗口和不带窗口不得命中同一份缓存（否则脏读）
- [ ] 窗口边界为闭区间；`since > until` 报错退出码 2；非法日期格式报错退出码 2
- [ ] `prep.py --since/--until` 同样可用（它才是 SKILL.md 推荐的默认入口）
- [ ] 留痕记录窗口（`extra.since/extra.until`），`--audit` 能看出"这次是在窗口内查的"
- [ ] 不给 `--since/--until` 时，行为与改动前**逐字节一致**（既有 320 passed 零回归）
- [ ] `--auto` 路由下窗口同样生效
- [ ] 文档改成"一条主干 + 两个约束"，三通道的旧说法同步修订；ADR 记录这次收敛

## 范围外（本轮不做）

- 不改 `--timeline` / `--literal` 的语义（它们是约束的退化形态，已被 #5 覆盖）
- 不做多时间窗 / 相对时间解析（"上周""国庆后"由 AI 换算成绝对日期再传，脚本不猜）
- 不做 FTS5（字面约束仍走 `LIKE`，量级够用）
- 不做跨 agent 窗口查询（隔离墙不变）

## 问题一：收尾问句缩回「动作」

### 矛盾在哪

同一份 `SKILL.md` 里，第 173 行明写：

```markdown
### 不限于「动作」

一个工具、一套结构、一份检查表、**一套范式判断**、**一个项目存档**、**一批参考图例**、
一条能改判断的结论——都行。动作只是最容易看见的一类。
```

但第 202-206 行，整件事最核心的那个触发，写成了：

```markdown
**② 收尾那一刻（最重要）** —— 每完成一个项目或一段活，先问一句：

> **这次的哪些动作可以留着下次用？**

不是问「学到了什么」（那是写日记），是问「哪个动作可以脚本化 / 模板化 / 清单化」。
```

**前面声明「不限于动作」，后面的执行句只问动作，还把范围进一步收窄成「脚本化/模板化/清单化」——
全是「做」类。** 想清楚的一个判断、攒下的一套范式，在这个问句下根本不会被想起。

### 为什么错

这个词是从开编日记里直接引用的：

> 下次项目收尾时应当默认问一句：这次的哪些动作可以脚本化？

**但那是它在「编程」这件事上的说法。** 它的活本来就是做动作，问句自然是问动作。
换成写作、研究、运营智能体，这个问句一个字都不适用。

而我们定过一条：**开编的答案是它的答案，不是标准。** 这里却把它的原话当成了通用问句。

### 应该是什么

回到判据——我们定的是「能省掉多少**重新想**和**重新做**」：

- **重新想** → 范式判断、结论、框架、图例
- **重新做** → 工具、模板、清单

收尾问句必须同时覆盖两条：

```markdown
**② 收尾那一刻（最重要）** —— 每完成一个项目或一段活，先问一句：

> **这次的哪些东西，下次能直接拿来用？**

「东西」不限定形态。想清楚的一个判断也是东西，攒出来的一份参考图例也是东西，
做完的一个项目存档也是东西。

不是问「学到了什么」（那是写日记），是问「哪些**以后不用重新想、不用重新做**」。
这个问句不必等用户提醒，收尾时默认执行。
```

## 问题二：技能库路径被写死

### 矛盾在哪

`SKILL.md:217` 的三级路径表：

```markdown
| **用户目录下**（技能库、桌面、其他 home 内的东西） | `~/` 开头 | `~/.dsh/skills` |
```

`SKILL.md:227`：

```markdown
`...longterm\\ ，总索引…` 和 `~/.agents/skills` 出现在同一段
```

`CONTEXT.md:62` 同样把 `~/.dsh/skills` 写进术语定义。

### 为什么错

`~/.dsh/skills` 是**这台机器、这个 harness（DSH）** 的位置。

换 Claude Code、Cursor、Cline、或其他 harness，技能库路径完全不同。
把它写进文档当范例，读者会照着抄——抄到别的环境就是错的。

**技能库位置是 harness 在运行时告诉你的事实，不是文档能规定的常量。**
而且全局技能库和项目技能库是两回事，各自位置也由 harness 给出。

### 应该怎么表达

三档判据本身没错（inside / home / external），错的是**拿具体路径当范例**：

```markdown
### 三种路径，三种写法

| 档 | 怎么认 | 该写成 |
|---|---|---|
| **inside** | 落在你自己的记忆区 / 工作区里 | 相对基准，如 `longterm/LONGTERM.md` |
| **home** | 落在用户目录下 | `~/` 开头 |
| **external** | 别的盘 / 别人的项目 | 保留绝对，标注「外部真源」 |

判据一句话：**这段路径跟着谁搬家？**

- 跟着 agent 目录 → 写相对
- 跟着用户账户 → 写 `~`
- 跟着另一个项目 → 只能绝对，但要说清它不是本区内容

**技能库在哪，问你的 harness。** 全局技能库和项目技能库各自的位置由它运行时给出，
文档不写死——不同 harness 不一样，写死了照抄就会错。

**同一个 `self.md` 里两种写法并存，是最典型的错**：
一段写 `~/`，另一段写绝对 home 路径——写 `~` 的那句能搬，写绝对的那句不能。
```

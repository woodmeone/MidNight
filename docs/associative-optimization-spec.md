## 1. 触发与背景

用户当天真实翻车：问"张娜啥时候问我问题的"，我拿"张娜 + 英语"去向量召回，结果把 9/7 的「番职大金融科技」漏了——因为那天聊的不是英语，而查询词里有"英语"。

复盘将此问题追溯到：**我们只是"借了 VCP 浪潮算法的一个点子"的精神化原创实现，并非 VCP 移植；且把这个想法放在了"事后加分"位置，锁不住检索方向。**

## 2. 对 VCP 的立场（开放借鉴，两档区分）

原则：**能借鉴就借鉴，不藏着掖着，把好的沉淀进自己的 skill。** 但分两档：

| 挡位 | 范围 | 动作 |

| 借思想/算法公式 | tag-gate、向量重塑、衰减调度、通用先人智慧 | 直接用 |
| 逐字拷贝实现/代码/文案 | VCP 源码、文案 | **必须先更新 ADR + 落 License 声明**（CC BY-NC-SA，涉及账号变现目标，不能裸抄裸用） |

**必须执行的流程护栏（P0.5）**：更新 `docs/adr/0001-original-implementation.md`（当前锁死"原创不摘抄"）→ 改为"借思想自由、借代码必留声明"。否则后续每借一段 VCP 代码都在违规。

## 3. 社区反馈的 VCP 痛点（合并进本 spec）

评论区原话与我们的判定：

> "很难，也没解决 vcp 的痛点，vcp 主要是破坏缓存。重任务过多注入上下文，导致幻觉奇高，注意力不集中。这俩都贼吃模型和 token，现阶段初用非常惊艳，但是用久了问题很多。"

| 痛点 | 判定 | 对应优化 |
|---|---|---|
| ① 破坏缓存 / 联想固化跑偏 | ✅ 合理 | P2 降权保鲜 + 弱边衰减（不删除） |
| ② 过多注入上下文 → 幻觉↑ / 注意力差 | ✅ 最有杀伤力，但**部分已解决** | 已存在预算收敛+去重；补 P1 深联想质量门槛 |
| ③ 贼吃模型和 token | ✅ 合理（主要指**找的过程**，非注入量） | P3 索引 + 缓存 |
| ④ 久用问题多 | ✅ 合理 | 无界增长 + 无维护 → P2 保鲜 |

**重要澄清**（避免被带偏）：
- ② 的"注入量失控"**已被本轮合入 main 的 PR**解决（`fit_to_budget` + `dedupe_results`）。剩余只有"深联想"那一截。
- ③ "token 贵"指的是**为了凑 top-k、每次把整个仓库全量扫描/全 tag 算余弦**（O(#chunks)+O(#tags)/次），**不是**把大量数据丢给模型。输出量本来就是 k 条。

## 4. 架构判断：VCP 架构 vs 我们架构

**结论：不是二选一，是"保留我们的骨架 + 外科手术式补一节"。**

- **不照搬 VCP 的重锤**：EPA（逻辑深度/世界观门控）、残差金字塔、PSR 犹豫度、霰弹枪查询、SVD 去重——为复杂多模态/海量对话流设计，对"个人老师笔记"过量，照搬就是评论区说的"吃模型吃 token"。
- **必须补的一环**：`tag-gate / 向量重塑 + tag-first 意图锁定`——把 tag 从"事后抬分"挪到"事前进候选筛选"。这是我们与 VCP 行为不一致（真实体验到翻车）的根因。
- **我们的骨架值得保留**：自包含、离线、轻量，且已比 VCP 更早解决了"上下文塞爆"。

一句话：**不是重写，是"把 tag 用早一点"。**

---

### 4.1 决策层 / 执行层分工（架构定论，2026-09-08 调研后锁定）

调研结论（VCP TagMemo 浪 潮 vs letta/MemGPT）：
> VCP 的 EPA（逻辑深度/世界观门控）、残差金字塔、PSR、霰弹枪、SVD **本质是用代码/算力去替代 LLM 的意图判断**（决策层伪判定）；letta 则是把记忆决策放进 LLM（AI 自治记忆管家），把成本押在推理侧。

Midnight 的定位 = **「AI 做决策 + 代码做机械召回」的混合**，比 VCP、letta 更干净：

| 层 | 谁做 | 做什么 | token |
|---|---|---|---|
| 决策层 | **AI（LLM）** | 理解意图、生成召回查询词、判断是否落库/归档（letta-写 思路）、是否需辩证口吻（PSR→用 LLM 一句话做，不做算法） | 极低：基本等于一个查询词 |
| 执行层 | **代码** | tag-first 门控 + 向量 KNN + tag 脉冲联想 + 去重 + 预算收敛 | 近 0（全离线） |

**由此得出两条铁律（token 不爆的前提）**：
1. **借 VCP 执行层（tag-first/向量重塑/脉冲）**，**不建决策层伪判定**（EPA/金字塔/PSR 类）——AI 已经免费代劳，复制即重复轮子+引入调参黑箱。
2. **AI 只判关键词、代码只做召回、AI 只收数据**：召回参数（k/budget/threshold）**锁死为代码安全默认，AI 不可逐次乱调**；注入量交给 `fit_to_budget` 封顶。

> 现有 gap：code 侧召回目前是 KNN 先行、tag 事后抬分（P0 未做，仅 6 成"联得准"）；深联想可进噪音（P1 门槛未做）。

## 5. User Stories（本轮验收语义）

1. **检索不被词带偏**：as 赖老师，I want, 即使把问题问岔（旧带 "英语"），青岚也能顺着"人(张娜)+话题(升学)"找到真正的记忆（番职大金融科技），so that 关键词带歪时不跑偏。
2. **旧印象不固化**：as 赖老师，I want 学生旧印象（如蒋之泰油盐不进）随时间变淡，so that 不盖住学生的成长变化。
3. **宁少勿滥**：as 赖老师，I want 青岚别把弱联想噪音倒进回答（深联想设门槛），so that 少而准、不拿旧账把人听懵。
4. **记得越久越快**（注意：是"找的过程"，不是注入量）：as 赖老师，I want 记忆越多、召回越快，so that 不因积累而越来越慢。
5. **记得久也记得干净**：as 赖老师，I want 记忆只降权不删除，完整保留且可手动翻到，so that 旧条目不腐坏、不占活跃召回顶层。

## 6. 优化方案（按收益/成本排队）

### P0 · 标签前置门控（tag-first gating）— 最低成本，最痛，先做
`recall_associative` 链路：tag 先于 KNN 进入候选筛选，不再只事后抬分。
- 保证 top-N 中必有"命中核心标签"的 chunk，标签从"事后投票"变"事前框候选"。
- 兑现 Story 1。

### P0.5 · 开放借鉴流程护栏（改 ADR）
`docs/adr/0001-original-implementation.md`：原创不摘抄 → 借思想自由、借代码必留 License 声明。

### P1 · 深联想质量门槛
深联想（语义相通但字不相干）加**激活强度门槛 + 条数硬上限**，弱联结不加入。
- 兑现 Story 3 剩余部分。抵押了评论区痛点②。

### P2 · 记忆保鲜：只降权、不删除
对长时间低价值 <关联边权重/对象权重> 自动衰减、陈旧条目调极低权重。**正文永远是源真相，不删。**
- 兑现 Story 2 + Story 5。防评论区痛点①④。

### P3 · 召回性能：索引 + 缓存
给全仓库扫描加倒排/FTS 索引 + 结果缓存，避免每次 O(全部) 余弦。
- 成本高，碰数据结构，单独一个 ticket。兑现 Story 4。防痛点③。

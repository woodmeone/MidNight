## 一、项目背景

### 1.1 为什么做这个项目

VCP（Variable & Command Protocol）是一个全栈自研的 AGI 运行时系统，它把"无状态、无记忆、无身体"的 LLM 改造成拥有持久记忆、时间感知、自主行动的 Agent。但 VCP 有四个问题：

1. **许可证限制**：CC BY-NC-SA 4.0，不能商用
2. **架构耦合**：全栈 Node.js + Rust + 多个数据库，部署成本高
3. **生态绑定**：依赖 VCP 服务端，不能独立运行
4. **复杂度溢出**：很多功能是锦上添花，核心价值只占 20%

**目标**：提取 VCP 最核心的 20% 价值（记忆、联想、跨端、心跳、路由），用最轻量的方式实现，原始创新，CC BY-NC-SA 4.0 许可（非商业）。

### 1.2 设计原则

| 原则 | 含义 |
|---|---|
| 完全自包含 | 不依赖任何外部服务，Python + SQLite 即可运行 |
| 原创实现 | 不复制 VCP 代码，独立完成 |
| 原子化 | 4 个独立 skill，可单独使用、单独升级 |
| 物理隔离 | 每个智能体独立数据库，数据不串 |
| 通用性 | 任何能跑 Python 的环境都能用 |


## 三、recall（记忆）——核心实现

### 3.1 实现原理

VCP 的记忆系统由三套引擎组成：TagMemo（浪潮算法）、TagMemoV10（不可变 Artifact）、RiverMemo（Rust 拓扑重排）。我们提取了最核心的"共现矩阵 + 脉冲传播"作为联想引擎，这是 VCP 联想记忆的"魂"。

**写入侧**（`ingest.py`）：
- AI 用 `write_file` 工具写日记文件到指定目录
- 日记格式：YAML frontmatter（maid/created/tags/importance）+ 正文
- `ingest.py` 解析文件 → 切块（按段落/512字符）→ 调 embedding API 向量化 → 写入 SQLite
- 同时更新 `tag_cooccurrence` 共现矩阵（同文件标签两两配对）

**存储侧**（`schema.py`）：
- SQLite 5 张表：`files`、`chunks`、`tags`、`chunk_tags`、`tag_cooccurrence`
- `chunks` 表新增 `importance`（冷热知识）和 `access_count`（访问频率）

**检索侧**（`recall.py`）：
- 向量最近邻检索（KNN）：查询向量化 → 余弦相似度 → Top-K
- 共现脉冲传播：激活标签 → 广度优先沿共现矩阵扩散 → 关联标签内容加入候选
- 时间加权：最近 7 天权重 1.0，7-30 天 0.5，30-90 天 0.2
- 重要性加权：high ×1.5，medium ×1.0，low ×0.5
- 截断控制：`truncate` 参数按比例截断输出

**联想侧**（`tag_network.py`）：
- 共现矩阵：两个标签在同一篇日记中出现 → 权重 +1
- 脉冲传播：BFS 广度优先，衰减因子 0.5，最大深度 2，强度阈值 0.1
- 种子标签：通过向量相似度从查询中感应最匹配的标签

### 3.2 与 VCP 的对比

| VCP 组件 | 我们的实现 | 简化程度 |
|---|---|---|
| TagMemo 浪潮算法 | 共现矩阵 + 脉冲传播 | 核心保留，去掉 EPA 投影/残差金字塔 |
| TagMemoV10 | 跳过 | 未实现 |
| RiverMemo Rust 内核 | 跳过 | 未实现 |
| 冷热知识 | importance 字段加权 | 简化版 |
| 元思考系统 | SKILL.md 引导 | 简化版 |
| Rust 向量索引 | SQLite 全量加载 | 小规模（<10万条）够用 |

### 3.3 物理隔离 vs 逻辑隔离

**VCP 的做法**：同一个数据库，用 `diary_name` 列过滤（逻辑隔离）

**我们的做法**：每个智能体独立数据库文件（物理隔离）

```
VCP 方案：单一数据库 + WHERE diary_name = 'Nova'
我们方案：~/.midnight/recall/Nova/recall.db（独立文件）
```

物理隔离的好处：
- 删除一个智能体直接删目录，不碰别的数据
- 一个库损坏不影响其他库
- Agent 直接调用自己的数据库，路径明确
- 并发写入无锁竞争

### 3.4 语义自动路由

新增 `auto_recall()` 函数，自动匹配查询到最合适的 agent：

1. 扫描 `~/.midnight/recall/` 下所有 agent 目录
2. 读取每个 agent 的 `agent.json` 描述文件
3. 对查询和所有 agent 描述做语义匹配（余弦相似度）
4. 选最匹配的 agent，在其数据库执行联想召回

```bash
python recall.py --query "帮我看看这段Python代码" --auto
# 输出：[自动路由] → 匹配到智能体「助教」(辅导学习编程, 相似度=0.xxx)
```

## 四、core（跨端统一）——实现原理

### 4.1 VCP 的 OneRing 机制

VCP 的 OneRing 是一个 messagePreprocessor 插件，触发语法 `[[OneRing::Agent::Frontend]]`：
- 每条消息（时间戳、来源）写入 SQLite
- 跨端请求时补充其他端的历史
- 标注 `[OneRing通知:...]` 来源标记

### 4.2 我们的实现

**写入**（`append.py`）：
- `append(session_id, source, role, content)` → 写入 `messages` 表
- 5 分钟内相同会话的相同内容自动去重（checksum + 时间窗口）

**读取**（`timeline.py`）：
- `get_timeline(session_id, limit, hours)` → 获取其他会话的最近消息
- 自动排除当前会话，按来源分组，按时间倒序

**输出格式**：
```
[跨端通知] 以下是来自其他会话的最近消息：
  来自 [电脑端] · 2026-08-20 14:30 🧑 用户: 帮我看看这个方案的可行性
  来自 [手机端] · 2026-08-20 10:00 🧑 用户: 记得提醒我晚上买牛奶
```

### 4.3 与 recall 的关系

- `recall` 存的是摘要日记（处理过的、打了标签的、可联想检索的长期记忆）
- `core` 存的是原始消息（未处理的、按时间线排列的、跨会话共享的短期上下文）
- 两者互补：recall 管"还记得吗"，core 管"刚才在另一个窗口说了什么"

## 五、pulse（自主心跳）——实现原理

### 5.1 VCP 的 Flowlock 机制

VCP 的 Flowlock 是 AgentAssistant 插件的核心协议：
- `[[Flowlock::Start]]` 启动心跳
- `[[Flowlock::NextHeartbeat::秒数]]` 设置下次心跳时间
- `[[Flowlock::NextPrompt]]...[[/Flowlock::NextPrompt]]` 自定义下一轮提示词
- `[[Flowlock::Complete]]` / `[[Flowlock::Fail]]` / `[[Flowlock::Stop]]` 终止动作
- 优先级：Complete > Fail > Stop > Start
- 服务器用 setTimeout 调度下一轮请求

### 5.2 我们的实现

**协议简化**：`[[Pulse::]]` 替代 `[[Flowlock::]]`

| 指令 | 含义 | 优先级 |
|---|---|---|
| `[[Pulse::Start]]` | 启动心跳 | 最低 |
| `[[Pulse::Next::180]]` | 下次心跳间隔 180 秒 | — |
| `[[Pulse::NextPrompt]]...` | 自定义下一轮提示词 | — |
| `[[Pulse::Complete]]` | 任务完成 | 最高 |
| `[[Pulse::Fail]]` | 任务失败 | 高 |
| `[[Pulse::Stop]]` | 主动退出 | 中 |

**循环引擎**（`pulse.py`）：
1. 发请求到模型 API（带 system prompt + 任务 prompt）
2. 解析回复中的 Pulse 指令
3. Complete/Fail/Stop → 终止循环，返回结果
4. Start/Continue → 计算间隔时间 → sleep → 构造下一轮请求（带上历史 + NextPrompt）
5. 安全防护：最大轮数 15，超时 300 秒

**核心代码**：
```python
def parse_pulse(response):
    # 先解析所有指令
    has_complete = bool(PULSE_PATTERNS['complete'].search(response))
    has_fail = bool(PULSE_PATTERNS['fail'].search(response))
    has_stop = bool(PULSE_PATTERNS['stop'].search(response))
    has_start = bool(PULSE_PATTERNS['start'].search(response))
    # 优先级：Complete > Fail > Stop > Start
    if has_complete: action = 'complete'
    elif has_fail: action = 'fail'
    elif has_stop: action = 'stop'
    elif has_start: action = 'start'
    else: action = 'continue'
```

## 六、compass（语义路由）——实现原理

### 6.1 VCP 的 SemanticModelRouter

VCP 的路由机制：
- 请求虚拟模型名（如 `VCPModelAuto`）
- 对最后消息做加权平均向量（0.7 user + 0.3 assistant）
- 与各 route description 算余弦相似度
- ≥0.18 的按相似度排序，选最优
- 容灾：500/503/429/401 自动降级

### 6.2 我们的实现

**配置**（`~/.midnight/compass/config.json`）：
```json
{
  "presets": {
    "default": {
      "routes": [
        {"name": "daily_chat", "model": "flash",
         "description": "日常聊天、闲聊、寒暄"},
        {"name": "research_and_coding", "model": "pro",
         "description": "信息调研、代码编写、调试"},
        {"name": "deep_reasoning", "model": "pro",
         "description": "复杂推理、逻辑分析"}
      ]
    }
  }
}
```

**路由引擎**（`route.py`）：
1. 查询向量化 → 与所有 route description 算余弦相似度
2. 过滤低于阈值（默认 0.18）的 route
3. 按相似度排序，选最优
4. 返回 `{model, route_name, score, fallback_models}`

## 八、关键架构决策

### 8.1 为什么用 Python 而不是 Node.js

VCP 原版是 Node.js + Rust。我们选 Python 的理由：
- `sqlite3` 是 Python 标准库，零额外安装
- `requests` 调 embedding API 比 Node 的 axios 简洁
- 未来加本地 embedding（`sentence-transformers`）Python 生态更成熟
- 测试框架 pytest 比 Node 的测试工具更成熟

### 8.2 为什么用 SQLite 而不是专用向量数据库

- 单文件、零配置、零服务
- 小规模（<10 万条记录）性能足够
- VCP 原版也用 SQLite 作为权威存储
- 专用向量数据库（Milvus/Qdrant）对单机项目过于复杂

### 8.3 为什么物理隔离而不是逻辑隔离

- 删除一个智能体直接删目录，不碰别的数据
- 一个库损坏不影响其他库
- Agent 直接调用自己的数据库，路径明确
- 并发写入无锁竞争

## 十、使用方式

### 10.1 写日记

AI 用 `write_file` 工具写 `~/.midnight/recall/<agent名>/dailynote/YYYY-MM-DD_HHMMSS.md`：

```yaml
---
maid: Nova
created: 2026-08-20T14:30:00
tags: [考试, 压力, 面试]
importance: high
---
今天讨论了面试，有点紧张，准备了三天。
```

### 10.2 入库

```bash
python ingest.py --agent Nova
```

### 10.3 召回

```bash
# 指定 agent
python recall.py --query "焦虑" --agent Nova

# 自动路由
python recall.py --query "帮我看看这段代码" --auto
```

### 10.4 跨端查看

```bash
python timeline.py --session "当前会话" --limit 10
```

### 10.5 心跳任务

```bash
python pulse.py --api-url "https://api.deepseek.com" --api-key "sk-..." \
  --model "deepseek-v4-flash" --prompt "分析文件" --rounds 15
```

### 10.6 路由判断

```bash
python route.py --query "今天天气怎么样"
# 输出：daily_chat → deepseek-v4-flash
```

# ADR-0002: md 源文件不作检索索引，检索只走库

- 状态：已接受（2026-10-21）
- 关联：Issue #5；SKILL.md「检索通道铁律」；`skills/recall/scripts/ledger.py`

## 背景

`~/.midnight/recall/<agent>/dailynote/*.md` 同时扮演了两个角色：**源**（`ingest.py` 的输入、备份本体、人可直接读的存档）和**索引**（Agent 回答"你还记得…"时 grep/read 的对象）。

第二个角色是自然长出来的，不是设计的：联想召回是**相关性排序**，答不了"最新一条是哪天 / 记到哪天 / 有没有提过某词"这类聚合与精确问题。没有正解时，读文件是唯一能给出确定答案的路——于是它成了理性选择，而不是纪律问题。

代价在真实使用中暴露（2026-10-21 的记忆体检）：直读源文件会同时绕过四层既有设计——身份隔离（明文目录 grep 一下就能跨 agent 读别人的记忆）、标签共现网与时间加权（退回关键词匹配）、去重与预算（长日记整篇灌入）、可移植性（迁到 hook 运行时/容器时 dailynote 不一定在）。

## 决定

1. **`recall.db` 是唯一检索索引**。md 文件是源，只经 `ingest.py` 单向流入库；任何"检索"语义的操作都不得落在 md 上。
2. **三条通道，一个数据源**：联想通道（默认，`prep.py` / `recall.py --query`）、确定性通道（`--timeline` / `--literal` / `--since` / `--until`，同库直查）、md 原文（仅用户显式授权，且回复须声明）。
3. **补齐能力而不是只加禁令**：把"记到哪天"这类问题变成库内一次 SQL，禁读才有正当性。
4. **可验证**：每次 CLI 检索追加一行 `retrieval_ledger.jsonl`，`--audit` 可反查，"走没走算法"从自述变成事实。
5. **默认行为不变**：新通道全是增量 flag，不给 flag 时输出与改动前逐字节一致。

## 理由

- **隔离是结构性的**：只要明文目录在可读范围内，"不要跨 agent 读"就是纪律；把检索入口收敛到库，隔离才是结构性的。
- **算法价值只在被使用时存在**：标签脉冲、时间加权、MMR、预算——跳过它们去读原文，等于把这些能力作废。
- **可移植性**：库是单文件，跟着 agent 走；md 目录依赖文件系统布局。hook 运行时只挂库就能召回。
- **诚实优于编造**：缺能力时 Agent 会去猜/去翻。补上确定性通道后，"没有这条记忆"才能被如实回答。

## 后果

- 正面：记忆问答有确定性正解（时间轴/字面），三通道共用同一套隔离、格式、预算与留痕。
- 正面：检索行为可审计（`--audit`），"我走了联想"不再是自述。
- 代价：多一个状态文件（jsonl），需要人按需清理；确定性命中依赖 `chunk_ngrams`/`LIKE` 的字面能力，跨语言改写（例如同义替换）只能靠联想通道。
- 约束：**不得**让 md 重新成为检索回退路径（例如"库里没有就 grep 一下"）。库没有就是没有，如实说。
- 注意：`dailynote/*.md` 仍是真相源，仍需按写日记协议维护；本 ADR 只剥夺它的**索引**角色。
- **实测补充**（2026-10-21，qinglan 区）：库内 508 条 file 记录 vs 磁盘 505 个 `.md`，其中 2 条记录的源文件已被删除，`--timeline` 仍能返回它们的内容。这说明**库比 md 更完整**——md 是"写入当时"的源，不保证长期存在；检索若依赖 md，就会随文件丢失而丢记忆。这条实测把"检索只走库"从设计偏好升级成了事实约束。

## 替代方案

- **物理隔离 md**（移出可读区/加密）：能强制，但破坏"md 是真相源、永不删"，且 ingest/备份/人工查阅链路要重写，否决。
- **只加禁令不改代码**：禁令压不住一个有真实需求支撑的行为，实测会绕回来，否决。
- **暴露 FTS5 作第四通道**：中文分词与迁移成本高，`LIKE` 在当前库量级够用，暂缓。

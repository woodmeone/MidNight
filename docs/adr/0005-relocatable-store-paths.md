# ADR-0005: 记忆库路径相对化——兼容老库，不强制迁移

- 状态：已接受（2026-11-14）
- 关联：Issue #11；`skills/recall/scripts/paths.py`、`ingest.py`、`recall.py`、`maintenance.py`；ADR-0002

## 背景

ADR-0002 说「库是单文件，跟着 agent 走」。实测打脸：

```
C:\Users\WoodMe\.midnight\recall\seagull\dailynote\2026-11-14_173000.md
C:\Users\WoodMe\.midnight\recall\qinglan\dailynote\2026-08-27_220734.md
```

`files.file_path` 存的是**绝对路径，带用户名**。库能走，路径不走——
换机器 / 换用户名，`file_path` 全断。迁移（打包搬到另一台机器）因此被硬阻塞。

这是本 feature 里唯一需要碰既有数据的改动。

## 决策

**兼容而不是强制迁移。**

- **写**：新数据存相对 agent 目录的路径，统一正斜杠
- **读**：`os.path.isabs()` 判定——老的绝对路径原样返回，新的相对路径按 `dirname(abspath(db_path))` 还原
- **两种共存**：零迁移也能跑；`--relativize-paths` 只是把老库也变成可搬的，不是前置条件
- **ingest 两次查**：先查相对路径，查不到再查绝对路径。只查相对会匹配不上老行 → 把同一篇日记当新文件插第二次
- **迁移只 `UPDATE files.file_path`**：绝不 DELETE / DROP / 碰 `chunks`；`--apply` 前自动备份

还原基准取 `dirname(abspath(db_path))` 而不是 agent 名——`recall(db_path)` 本来就拿不到 agent 名，
而 db 所在目录天然就是 agent 目录。

## 理由

- **迁移是可选优化，兼容是刚需**。强制迁移意味着「没迁移的库不能用」，一次失败就卡住整个记忆。
  兼容方案让最坏情况退化成「路径是绝对」，而不是「读不到」。
- **先 abspath 再 dirname**：`recall.py` 支持 `--db recall.db` 这种裸文件名，
  直接 `dirname('recall.db')` 得空串，还原会变成相对当前目录的错路径。
- **正斜杠**：Windows 反斜杠进 JSON / 跨平台时易出转义问题，正斜杠两边都能被 `os.path.join` 处理。
- **不顺手把老行改成相对**：`ingest` 的职责是入库，迁移是 `maintenance` 的职责。
  混在一起会让「入库」变成隐式迁移，出问题时无从追溯。

## 补充：这条也管长期内容（Issue #14）

`#11` 只管住了数据库。长期内容是纯文件系统，没有库——绝对路径照样会从那里漏：

`#9` 的开机清单输出 `→ D:\Project\...\LONGTERM.md`，智能体照着模仿，
就把自己的索引写成绝对路径。**展示即示范**，坏的示范比没有示范更糟。

修法（`#14`）：

- 开机清单渲染成 `→ LONGTERM.md（根 <abs>）`——相对路径在前，绝对只作定位
- `boot.py --check` 扫索引，按**是否落在 root 内**分两级：
  - `inside` 必须改（搬机器必断）
  - `outside` 是外部真源指路，写相对无意义，当前写法合理
- `--strict` 只为 `inside` 退 1

**为什么分级而不是一刀切。** 真库验证时，开编索引里有 4 条 `D:\Project\...`，
全是「活原件在别的盘、这里只留指路」。一刀切会把它们判成错误——
而过严的检查器，结局是被无视。判据要说清「哪种绝对算错」，否则等于没说。

## 后果

- 正面：整个 `<agent>/` 目录 `copytree` 到任意路径，`--timeline` / `--literal` 照常工作（有测试锁定）。
- 正面：老库不动也能用；`--relativize-paths` dry-run 为默认，真跑前自动备份。
- 代价：读取侧多一层 `isabs` 分支——两套格式并存，读代码时要同时想到。
- 代价：库外路径（如 `%TEMP%` 里的测试残留）**搬不走**，只能跳过并保持绝对。
  实测 qinglan 595 条里 1 条属于这种，跳过是正确行为，不是失败。
- 约束：**新代码不得再往库里写绝对路径**。任何新增的「路径字段」都要先过 `stored_path`。
- 注意：资产/长期内容走文件系统且本来就存相对工作区的路径，不在此约束内——
  但如果将来给它们建索引表，同样口径。

## 替代方案

- **强制迁移（读了就迁移 / 启动即迁移）**：实现简单，一次搞定。否决理由是迁移失败会连累读取，
  且要处理「迁移到一半断电」的部分写入状态。兼容方案没有这个失败模式。
- **在 `files` 表加一列 `rel_path`，双列并存**：语义最清晰，但要改 schema 且老库要填两遍。
  否决理由是不值得——`isabs` 判定已经能区分两套格式，不需要新列。
- **把 dailynote 移出 agent 目录，路径写成 `<agent>/dailynote/...` 前缀形式**：
  可行但引入第三种格式（既不是绝对也不是相对），读取侧要三分支。否决。

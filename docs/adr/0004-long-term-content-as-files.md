# ADR-0004: 长期内容归文件系统，开机清单只给索引

- 状态：已接受（2026-11-14）
- 关联：Issue #9 / #10 / #12；`skills/recall/scripts/boot.py`、`self_model.py`；`SKILL.md`

## 背景

智能体每次开工是空白的。它手里攒着三样自己的东西——人设、长期内容、记忆——但会话第一条一个都看不见。

实证（`kaibian`，2026-11-14 日记）：

> 失：我还是先按文档思路做了一遍，是用户提醒才想到存可执行资产。
> 下次项目收尾时应当默认问一句：这次的哪些动作可以脚本化？

它**已经建出**六类目录 + 一份总索引（`tools/ snippets/ templates/ checklists/ kb/ refs/`），
却在干活时看不见它们。那一声「用户提醒」，就是这个 ADR 要消掉的东西。

`session_start.py` 里早就有 `compile_identity_summary()`，但它只编译 self.md 字段，
**没有任何流程调用它，也不含长期内容**。零件有，没装上。

## 决策

### 1. 长期内容归文件系统，不进数据库

三种形态否决了入库：

- **形态不对**：脚本、图片、模板不是「正文」。灌进 `chunks` 既不能执行也不能显示，召回了也没用。
- **语义冲突**：`importance` 权重和 `--decay` 是「印象淡出」语义。套上去会变成
  「我的代码过时了所以它消失了」——荒谬。
- **生命周期相反**：`chunks` 没有删除语义（只增不减是第一性质），长期内容必须能建、能改、能退休。

### 2. 开机清单只给「我是谁 + 我有什么」，且**不设字数上限**

`boot.py` 产出：人设摘要 + 长期内容类目计数 + 索引路径。超 2000 字只在末尾追加提醒，**不裁剪内容**。

### 3. 能力与同伴**不进**清单

| | 谁生的 | 为什么不进 |
|---|---|---|
| 能力 | 外部给（技能库） | 存在性写一句指路就永久有效；经验靠日记沉淀 |
| 同伴 | 外部给（目录） | 遗漏代价低（想不起 mira 还能自己干，想不起 image-gen 是真不知道怎么做——不对称） |

**自己长出来的要扫，外面给的只要一句指路。**

### 4. 人设是长期内容的第 0 类

`self.md` 不是并列的另一件事，它就是长期内容，而且最核心。差别只在精度：每次全给，其余按需加载。
定海锚只读——不是它不算长期内容，而是长期内容里唯一禁止自改的那一段，**身份不能漂**。

### 5. 只给意识，不给判据

维护由智能体自己判断。**不设准入四问、不设 90 天退役算法**。

触发是三个时刻（建时 / 收尾 / 索引指空），不是定期——定期靠额外意志力，收尾那一刻素材还在手上。

## 理由

- **给模板 = 抽掉它最像智能的那部分**。智能体的本质是「先抓第一性原理的基底，再补充细节」。
  系统该给的是**抓基底的材料**（判据、方法、边界、真实案例），不是**基底本身**（模板、分类表、标准答案）。
- **规则管得住输出，管不住判断**；而且规则会过时——120 字对写作智能体太多、对代码智能体太少。
- **三级加载就是「先基底后细节」在数据层的落地**：每一级只给「够判断要不要再往下」的信息。

调研佐证：ReMe（[arXiv:2512.10696](https://arxiv.org/abs/2512.10696)）批评「被动积累」范式，
其 `utility-based refinement` 做的正是「自主剪除过时的」。但它与
[When Should Experience Become Parameters?](https://zenodo.org/records/21175566)
都指向「selection, not volume」——**是选择，不是数量**。本 ADR 的选择是：把选择权交给智能体，
系统只提供判断所需的最小材料。

## 后果

- 正面：开编的六类目录从「存在但看不见」变成「开机就看见」，收尾时的自问不必再靠用户提醒。
- 正面：长期内容可自由增删改，不污染记忆的只增不减语义；库删了记忆还在，记忆删了文件还在——**双向解耦**。
- 代价：多一个入口（`boot.py`），需要 harness 侧接 session-start hook 才真正自动——本轮只交付命令与纪律。
- 代价：不设上限意味着**清单可能很长**。缓解是那句 token 提醒 + 智能体自己的判断，没有硬闸门。
- 约束：**别再给长期内容加判据**（准入标准、字数上限、定期检查）。想加之前先读本 ADR 的「理由」。
- 注意：`longterm/` 目录系统不预设、不创建。不存在时 `boot.py` 报「不可用」，不当错误。

## 替代方案

- **长期内容进 `chunks` 表**：能复用现有向量召回，但三种形态冲突（见决策 1）各自都足以否决。
- **开机清单给 120 字硬预算 + 六级裁剪表**：原型做过，能跑。否决理由是它把取舍权拿走了——
  阈值对写作智能体太多、对代码智能体太少，且裁剪必然要决定「砍哪条」，那是判断，不是格式。
- **能力清单进开机清单**：每会话白付一份自己用不上的目录。经验层（哪个顺手）已经在记忆里，
  存在性靠 self.md 一句指路即可。
- **准入四问 + 90 天退役算法**：原型写过。否决理由是违背「智能体自己判断」这条根，
  且 90 天会误杀季节性内容（春节模板一年用一次）。

# ADR-0001: 原创实现，不复制 VCP 代码

- 状态：已接受（2026-08-20）；许可决定更新（2026-08-27）
- 关联决策：完全自包含

## 背景

我们计划把 VCP(VCPToolBox) 的核心能力（记忆、跨端、心跳、路由）提炼成一组原子化 Reasonix skill。讨论开始时，直接复用 VCP 的源码是候选方案之一。

## 决定

- **不复制** VCP 的 JS 代码（`ingestionPipeline.js`、`RAGDiaryPlugin.js`、`AgentAssistant.js` 等）。
- **不引用** VCP 品牌、商标、名称到 skill 命名中。
- **受其设计思想启发**，用 Python 全新实现核心逻辑。
- **项目许可证**：CC BY-NC-SA 4.0（非商业使用），见根目录 `LICENSE`。

## 理由

1. **许可证约束**：VCP 使用 **CC BY-NC-SA 4.0**（`package.json` 与根目录 `LICENSE` 确认）。其中：
   - **NC（非商业）**：直接使用/衍生 VCP 代码的作品不能用于商业目的。
   - **SA（相同方式共享）**：基于 VCP 代码的衍生作品必须用相同或兼容许可证发布。
   - **商标不授权**（第 2(b)(2) 条）：许可证不授权使用 VCP 名称/品牌。
2. **法律隔离**：版权保护的是"表达"（具体代码），不保护"思想"（算法设计）。用 Python 重新实现算法，产出的是全新的表达，不继承 VCP 的许可证义务。
3. **项目自身定位**：本项目的产品方向是非商业的创意/研究性质，选择与 VCP 相同的 CC BY-NC-SA 4.0 许可，保持一致的价值观。

## 后果

- 正面：法律上完全干净，不继承 VCP 的许可证义务。
- 正面：技术解耦——不依赖 VCPToolBox 的版本演进和进程。
- 代价：需要重新实现向量化、检索、联想等核心逻辑（我们有 VCP 源码作为设计参考，成本可控）。
- 注意：后续维护时仍需注意**不引入 VCP 代码**，包括不从其源码直接摘抄关键函数。

## 替代方案

- 直接复制 VCP 代码：被 NC + SA 约束，且违背原创原则，否决。
- 用 VCP 名字命名：商标侵权风险，否决。
- 半依赖（通过 API 调 VCP 服务）：违背"完全自包含"解耦目标，且保留运行时依赖，否决。
